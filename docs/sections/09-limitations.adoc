== Known Limitations

Honest status: what works, what is stubbed, and what is next.
This chapter overrides any optimistic reading of earlier chapters.

=== What is real today

* Analysis, mem-index, query AST/parser, Boolean execution, and the
reference oracle.
* Persistent `.seal` segments with crash-safe publication and
verified reads.
* Delta+varint postings compression with measured benchmarks.
* Generations, tombstones, shadowing, `index merge` / `index delete`.
* Exhaustive field-weighted BM25 with phrases, snippets, `--explain`.
* CLI: `index`, `search`, `index stats|verify|merge|delete`.

Everything else in the tree is an honest stub that names its milestone
(`crawl`, eval metrics, distribution, HTTP API, UI, advanced ranking).

=== What is explicitly not here yet

* Skipping retrieval (WAND / Block-Max WAND verified `==` exhaustive)
* Typo tolerance and autocomplete structures
* Crawler (frontier, politeness, robots, dedup, HTML ingestion)
* Relevance science (graded judgments, nDCG@10 regression)
* Distributed sharding, replicas, rebalancing
* Caches with benchmark justification
* HTTP API, search UI, operations dashboard

=== Limits to design around

* Corpus formats today are `.txt` / `.md`; other files are counted
and skipped.
* Ranking is lexical BM25 only — no authority, freshness, or semantic
signals yet.
* Single-node, local-first: no sharding, replication, or global-IDF
coordination in this tree.
* Performance numbers cover codecs and small corpora; large-corpus
QPS / p99 claims are `TBD (unmeasured)` until the benchmark corpora land.

WARNING: Do not present roadmap boxes from <<architecture,Architecture>>
as working features in external communication.
The `README.md` status line and the milestone list in
`docs/architecture.md` are the public truth until the code proves otherwise.

# ADR 019: axum JSON API With a Static Page, React Deferred

Recorded after milestones 19–20 implementation. Applies to
`sealion-api` and `sealion serve`.

## Context

Spec §76–83 wants a search API, admin API, traces, metrics, a polished
product (§78: React), and an ops dashboard (§81). A full React build
chain is a separate project from the engine.

## Decision

- **axum 0.7** JSON API (the one framework-shaped dependency, justified:
  routing + JSON + graceful binding with no hand-rolled HTTP parsing):
  `/api/search` (trace timings per stage, explicit `partial`),
  `/api/complete`, `/api/admin/status|metrics` (Bearer-gated when
  configured, open otherwise for development).
- **Static single-file search page** (live autocomplete, highlighted
  snippets, partial badge) consuming exactly the contract a React app
  would: same endpoints, same shapes. React build deferred, not the API.
- **Query-result LRU lives here**: the server is the first long-lived
  process where cross-request reuse pays (measured 4× at 0.67 hit rate);
  CLI/coordinator bypasses stay documented.
- Admin auth is a shared-secret Bearer (correct scope for a demo;
  OIDC/LDAP is deployment work per `docs/deployment-demo.md`).

## Consequences

- `tests/serve.rs` locks the contract live (search/complete/status/
  metrics shapes, token gate, 400-not-500).
- The ops dashboard (§81) is admin JSON + CLI status today; a React
  console is the natural next slice.
